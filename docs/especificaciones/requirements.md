# REAKT - School Requirements

## Source

This document summarizes the requirements supplied by E.E.S.T. N°4 for the integrative project.

The original source is the project requirements document provided by the team.

Do not replace school requirements with assumptions from general software practice.

## Minimum technical requirements

The project must integrate:

- a microcontroller
- at least one sensor/data acquisition mechanism
- processing and decision logic in firmware
- Bluetooth and/or Wi-Fi connectivity
- an external device/server communication path
- a mobile and/or web dashboard
- a documented database location and integration

Additional communication such as ESP-NOW is optional in the school requirements, but it adds technical value to the project.

## 6th-year milestones

### Advance 1 - Design and Planning

Electrónica Digital:

- complete electrical schematic
- firmware flowchart
- detailed weekly schedule
- beginning of field/project documentation

Lenguajes Electrónicos:

- dashboard architecture
- technology selection
- wireframes/mockups
- technology stack definition

### Advance 2 - Hardware and Base Firmware

Electrónica Digital:

- assembled and organized prototype circuit
- at least one sensor working with the microcontroller
- at least one actuator responding to firmware
- risk and contingency identification

Lenguajes Electrónicos:

- basic functional interface with at least one screen
- initial app/microcontroller connection
- first visible dashboard data
- configured code repository

### Advance 3 - Integration and Testing

Electrónica Digital:

- integrated hardware + firmware
- documented integration tests
- corrections from Advance 2
- updated cost analysis

Lenguajes Electrónicos:

- dashboard views implemented
- connected working database
- demonstrable bidirectional communication
- draft user manual

### Advance 4 - Final Prototype / Exhibition

Electrónica Digital:

- fabricated/assembled PCB
- fully functional prototype
- finished and presentable enclosure
- complete field documentation
- photo/video process record

Lenguajes Electrónicos:

- fully functional application/dashboard
- production database
- live demonstration
- documented and backed-up source code

## Critical approval condition

The prototype must function during the final exhibition.

The supplied school document states that a non-functional project has a maximum grade of 4 regardless of other criteria.

Therefore reliability and demonstrable functionality are project-level priorities.

## 6th-year final deliverables

Hardware/Firmware:

- functional prototype
- finished enclosure
- complete and foliated field documentation
- final electrical schematic
- process photo/video
- approximate materials budget
- source code when requested

Software:

- functional web/mobile application
- operational dashboard
- connected/documented database
- data architecture description
- documented source code
- live demonstration

## 7th-year deliverables

Proyecto y Diseño:

- continuation of field documentation
- teacher diary
- formal technical report according to IEEE standards
- Spanish and English versions
- working prototype
- project web folder

Emprendimientos Productivos:

- project summary
- web folder
- user manual
- digital presentation
- logo/isotype material
- triptych
- commercial brochure
- SWOT/FODA analysis
- GANTT
- PESTEL
- ROI
- development/production budget

## Important documentation distinction

The supplied requirements state that the complete formal technical report is not a required 6th-year approval deliverable. The field/project documentation is the main 6th-year tracking document.

The complete formal technical report is developed in 7th year.

## Team workflow

The team is responsible for maintaining evidence of progress, documentation, source code and prototype development.

Codex may help generate technical artifacts, but it must not fabricate evidence of physical tests, teacher approval, measurements or completed deliverables.
