01 · El proyecto

Entrenar. Medir. Analizar. Evolucionar.

REAKT busca transformar un entrenamiento basado principalmente en percepción y repetición en una experiencia donde las respuestas del deportista puedan registrarse, procesarse y analizarse.

01

Problema

Los entrenamientos de reacción y coordinación pueden resultar difíciles de medir de manera objetiva cuando no existe un sistema que registre tiempos, aciertos, errores y evolución.

02

Propuesta

Una red de módulos físicos permite generar estímulos y detectar respuestas, mientras el sistema centraliza los eventos y la aplicación transforma los datos en métricas comprensibles.

03

Objetivo

Construir una plataforma de entrenamiento configurable que permita registrar sesiones, comparar resultados y visualizar la evolución del deportista.

04

Escalabilidad

La arquitectura está pensada para incorporar nuevos modos, métricas, módulos y funciones sin tener que rediseñar completamente el sistema.

03 · Entrenamiento

Modos diseñados para medir distintas capacidades.

Cada modalidad puede tener una configuración específica, pero utiliza una estructura de datos común para registrar los resultados.

01 · MEMORIA

Recordar y reproducir.

  • Patrones de estímulos
  • Secuencias progresivas
  • Aciertos y errores
  • Memoria de trabajo
02 · AGILIDAD

Responder y desplazarse.

  • Cambios rápidos
  • Secuencias variables
  • Tiempo de ejecución
  • Precisión
03 · REFLEJOS

Responder al estímulo.

  • Activación aleatoria
  • Tiempo de reacción
  • Aciertos y errores
  • Precisión
04 · VELOCIDAD

Ejecutar en el menor tiempo.

  • Duración configurable
  • Velocidad de aparición
  • Objetivos y golpes
  • Velocidad máxima
05 · RESISTENCIA

Mantener el rendimiento.

  • Rounds e intervalos
  • Descansos configurables
  • Dificultad progresiva
  • Rendimiento por round
06 · PRECISIÓN

Acertar el objetivo.

  • Aciertos y errores
  • Porcentaje de precisión
  • Objetivos configurables
  • Control de rendimiento
07 · COORDINACIÓN

Sincronizar respuesta y movimiento.

  • Patrones de módulos
  • Orden y secuencia
  • Tiempo de ejecución
  • Errores de coordinación
CONFIGURACIÓN ESPECIAL

Entrenamiento personalizado

Permite combinar objetivos como velocidad, resistencia, precisión y reflejos, seleccionar hasta 6 patrones y ejecutarlos en orden o de manera aleatoria. No se considera un octavo modo, sino una forma flexible de configurar una sesión.

04 · Desarrollo

Del prototipo al sistema funcional.

El desarrollo se divide en etapas para validar hardware, firmware, comunicación y software antes de integrar todo el sistema.

01

Arquitectura y diseño

Definición del sistema, modos de entrenamiento, flujo de datos, interfaz y stack tecnológico.

02

Hardware y firmware base

Prototipo en protoboard, pruebas de sensores y actuadores, ESP32 y ESP32-C3.

03

Comunicación

Validación de ESP-NOW entre módulos y gateway, y posterior comunicación externa mediante Wi-Fi.

04

Aplicación

Flutter + Dart, configuración de entrenamientos, visualización de datos, historial y estadísticas.

05

Backend e integración

Supabase/PostgreSQL, persistencia de sesiones, usuarios y métricas, e integración con el hardware.

06

Prototipo final y exposición

Integración completa, pruebas, documentación, presentación y demostración del sistema funcionando.

05 · Aplicación

Los datos también entrenan.

La aplicación móvil permitirá consultar sesiones, visualizar tendencias, mantener rachas y detectar evolución del rendimiento.

⌁

Inicio

Resumen de la última sesión, métricas principales, racha y acceso rápido al entrenamiento.

◷

Historial

Calendario de días entrenados, sesiones individuales y métricas de cada entrenamiento.

↗

Estadísticas

Evolución de velocidad, precisión, reacción, golpes, duración y resistencia.

★

Récords

Mejores resultados personales y logros desbloqueados mediante condiciones de entrenamiento.

Base de datos

La arquitectura prevista utiliza Supabase, basado en PostgreSQL, para almacenar usuarios, configuraciones, sesiones, métricas e historial. El ESP32 Gateway se comunicará mediante Wi-Fi con el backend, mientras que la comunicación entre los módulos físicos utilizará ESP-NOW.
